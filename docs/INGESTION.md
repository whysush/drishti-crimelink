# CLink — Data Store Go-Live (make the app run on Catalyst Data Store)

To satisfy capability #6 (relational DB → **Catalyst Data Store**) the engine can read
from Data Store instead of the bundled CSVs. The engine is already wired for this:
`CLINK_SOURCE=auto` → it tries Data Store, and falls back to the bundled CSVs if the
tables aren't there yet (so nothing ever breaks). `/health` and `/stats` report the
active `data_source`.

### Steps (console — ~10 min)
1. **Console → Data Store → Import Data**, and import each CSV from `seed/csv/`.
   The engine reads these **11 tables** (import at least these; all 28 is fine too):
   `CaseMaster, ChargesheetDetails, Accused, Victim, ComplainantDetails,
   ActSectionAssociation, Unit, District, CrimeHead, CrimeSubHead, GravityOffence`.
   Import creates the table from the CSV headers automatically (types can stay text —
   the engine coerces dates/numbers from strings).
2. **Enable full-text Search index** on `CaseMaster.BriefFacts` and `Accused.AccusedName`
   (covers capability #10 — full-text search within Data Store).
3. **Recompute from Data Store** (the engine caches; this forces a reload):
   ```
   curl -X POST https://crimelink-927199644.development.catalystserverless.com/server/crimelink_function/recompute
   ```
4. **Verify it's now on Data Store:**
   ```
   curl -s https://crimelink-927199644.development.catalystserverless.com/server/crimelink_function/stats
   # -> "data_source":"datastore"
   ```
If `data_source` shows `bundled-csv`, the tables aren't found yet — re-check the table
names match exactly and re-run step 3.

# CLink — Tier 0 Ingestion Runbook

Goal: get the spine live — create the Data Store tables, load the seed CSVs, and
run the proof-of-life query. ~15 min in the Catalyst console.

Data source right now: **synthetic seed** in `seed/csv/` (19 CSVs, generated by
`seed/generate_seed.py`, deterministic). Headers match Data Store column names
exactly, so bulk import auto-maps. Real KSP data drops into the **same tables** later.

> Catalyst Data Store tables are created in the **console / Admin API, not the CLI**,
> so steps 1–2 are console actions. Column specs below make that unambiguous.

## Step 1 — Create the tables (Console → Data Store → New Table)

Conventions: every table auto-gets `ROWID`/`CREATEDTIME`/`MODIFIEDTIME` — don't add them.
Type key: **BI**=Bigint, **I**=Int, **D**=Double, **V**=Varchar, **T**=Text, **DT**=DateTime, **B**=Boolean.
`uidx`=mark column "Unique", `idx`=add a normal index, `FTS`=enable full-text Search index on it.

## Step 2 — Bulk import the CSVs (Console → Data Store → table → Import Data)
- Import `seed/csv/<Table>.csv` into the matching table. Order doesn't matter (we join on
  domain keys, not enforced FK constraints).
- Map "first row as header"; column names line up 1:1.
- Each file is small (largest ~1.5k rows) — well under console import limits.

## Step 3 — Prove the spine (Console → Data Store → Query / ZCQL)
```sql
SELECT COUNT(ChargesheetDetails.CSID) FROM ChargesheetDetails WHERE ChargesheetDetails.cstype = 'C'
```
Expect **464**. Then:
```sql
SELECT CaseMaster.CaseMasterID, CaseMaster.CrimeNo, CaseMaster.PoliceStationID,
       CaseMaster.latitude, CaseMaster.longitude, ChargesheetDetails.cstype
FROM CaseMaster
JOIN ChargesheetDetails ON CaseMaster.CaseMasterID = ChargesheetDetails.CaseMasterID
WHERE ChargesheetDetails.cstype = 'C'
LIMIT 50
```
Rows returned = **spine is alive**. Tier 1 (linkage engine) is now unblocked.

## Loading REAL KSP data later
Same tables. Path depends on format (see decision tree in `docs/TIER0_SCHEMA.md`):
- Clean per-table CSVs → repeat Step 2.
- Needs transform / nightly automation → an SDK loader Function reading CSVs from **Stratus**
  (not File Store) and bulk-writing via `app.datastore().table(...).insert_rows(...)`.
  Wire that as a `crimelink_function` admin route once the console spine is confirmed.
- Ground truth for engine evaluation (planted series → member CrimeNos) is in
  `seed/ground_truth_series.json` — use it to score Tier-1 precision/recall on the seed,
  then discard when real data replaces the seed.

## Local re-verification (no console needed)
`python3 seed/generate_seed.py` regenerates identical CSVs. The join + integrity + separability
checks that validated this seed are reproducible from the CSVs with stdlib only.
